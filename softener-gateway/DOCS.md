# Softener Gateway Documentation

Softener Gateway is intended primarily as a Home Assistant add-on for compatible
EcoWater/iQua-family water softeners and branded devices built on the same platform,
including Viessmann, EcoWater, North Star, Morton, Whirlpool, Rheem, GE and Kenmore
devices.

The gateway converts a compatible softener from a cloud-based device into one that
can be controlled fully locally. It also exposes more device information and
configuration options than the iQua app.

## Basic Setup

1. Install **Softener Gateway** from this Home Assistant add-on repository.
2. Use the companion flasher tool from `tools/softener-certs-flasher` to prepare the
   device and generate the endpoint certificate and private key.
3. In the flasher, set `Replacement endpoint host` to the DNS name of the Home
   Assistant host that runs this add-on, or use the machine's IPv4 address directly.
4. Keep `Replacement endpoint port` at `8883` unless the add-on is configured to
   listen on a different port.
5. Do not use `.local` names such as `homeassistant.local`; tested devices did not
   resolve mDNS names. Use an IPv4 address when debugging connection problems.
6. Paste the generated `softener-gateway.crt` into `endpoint.certificate`.
7. Paste the generated `softener-gateway.key` into `endpoint.key`.
8. Keep `mode` set to `local` unless you specifically need bridge mode.
9. Start the add-on and open **Softener Gateway** from the Home Assistant sidebar.

## Modes

### Local Mode

Local mode is the default and recommended mode. The softener connects to the add-on,
and the add-on responds locally. In this mode, available device data is refreshed
continuously, including flow and runtime values.

### Bridge Mode

Bridge mode connects the softener to the add-on and forwards device traffic to the
original AWS IoT endpoint. Use it when you still need the cloud path, or when
collecting diagnostic data before switching to fully local operation.

Bridge mode requires the original device certificate and private key from the
device's original `aws_certs` partition. Available data appears only when it is
exchanged between the softener and the cloud, which normally happens rarely and when
the iQua app is being used.

## Main Options

- `mode`: `local` or `bridge`; default is `local`.
- `unit_system`: `metric` or `imperial`; default is `metric`.
- `endpoint.certificate`: PEM certificate served to the softener; use the generated
  `softener-gateway.crt` file by default.
- `endpoint.key`: PEM private key for the endpoint certificate; use the generated
  `softener-gateway.key` file by default.
- `endpoint.port`: TLS MQTT listener port inside the add-on; default is `8883`.
- `aws.host`: original AWS IoT endpoint host; required only for bridge mode.
- `aws.port`: original AWS IoT endpoint port; default is `8883`.
- `aws.certificate`: original device certificate; required only for bridge mode.
- `aws.key`: original device private key; required only for bridge mode.
- `aws.check_hostname`: verifies the original AWS endpoint hostname in bridge mode.
- `session_log`: saves bridge session logs to the Home Assistant shared folder.
- `mqtt.enabled`: enables MQTT publishing and Home Assistant discovery.

## HTTP API

The add-on provides a local HTTP UI and a documented HTTP API. The API is documented
with OpenAPI, and Swagger UI is available at `/docs`.

Use the API if you want to build your own integration, automation or external tool
without going through Home Assistant entities.

## MQTT

MQTT publishing is optional. When `mqtt.enabled` is true, the add-on can publish
device state to an MQTT broker and create Home Assistant discovery entities when
`mqtt.homeassistant_discovery` is enabled.

Configure `mqtt.host`, `mqtt.port`, `mqtt.username`, `mqtt.password`,
`mqtt.client_id` and `mqtt.topic_prefix` for your broker.

## Certificate Flashing Tool

The flasher prepares the softener's `aws_certs` partition so the device connects to
this local gateway instead of the original cloud host. It creates backups, verifies
readbacks, validates rebuilt payloads and refuses to continue when it cannot keep the
process controlled.

Read `tools/softener-certs-flasher/README.md` before flashing. The final risk remains
with the user.

## Safety Notes

- Keep private keys, flash dumps, packet captures and session logs private.
- Do not publish files generated by the flasher.
- Recovery backups are device-specific.
- Bridge logs may contain device identifiers and cloud payloads.
